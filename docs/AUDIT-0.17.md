# 0.17.0 升级复核（2026-11-20，未发布工作树）

范围：对照 v0.16.9 与当前工作树，重点检查 Project 从拖放、模型路由到两个 Markdown 文件写入和撤销的完整流程。编辑器、归档、设置迁移等沿用全套回归测试。以下是本次确认并修复的问题，不是对其他路径无缺陷的保证。

| 触发条件 | 旧行为及修复 |
| --- | --- |
| AI 生成期间，其他应用创建同名项目 | 普通 rename 可覆盖刚出现的文件。新建改为独占发布；冲突时项目和源便签都不改。 |
| 新建评估结束后修改便签、或在等待期间切换项目目录 | 确认动作可能沿用旧评估、向新目录的同名项目提交。确认时核对源文件版本，拖放 RPC 核对预期目录。 |
| `PROJECT: []` 或旧 `PROJECTS:` 的多行列表 | 空模板被误判已有项目，已有列表反而可能绕开判定。判断、显示和写入共用顶层字段读取，支持列表及带引号的键，原始 BOM 和行尾不被改写。回写后将超出扫描上限时也拒绝写入。 |
| 向空 YAML 头的索引补充进度 | 进度可能插到 YAML 前，使 Obsidian 不再识别属性。整稿修订时由 Host 保留原 YAML/BOM，模型只负责正文；撤销还原两份原文。 |
| 两个文件别名指向同一位置，或锁顺序相反 | 双文件操作改为先解析真实路径、去重并按固定顺序加锁；独立文件的校验仍在锁内执行。 |
| 模型目录异常或没有可用默认模型 | 明确按 provider 查询，兼容异步枚举，隔离单个 provider 的同步异常与异步拒绝；指定引擎不依赖默认引擎可读。并核对本机 DSH 安装包的 `listProviders()` 和 `listModels(provider)` 接口。 |
| 任务完成早于 RPC 回执，或在后台被 Host 回收 | 回执和任务快照任一更新均会重新匹配；已见任务过期时释放新建状态。卸载会中止仍在生成的 Project 任务。 |
| 快速重复拖入、进入菜单时短暂失去拖放目标 | 新操作不再静默替换上一计时器；菜单允许短暂跨越空隙，停靠后的菜单项保留原生 Enter 选择。项目生成不再误显示为评论，列表在实际写入或撤销后刷新。 |
