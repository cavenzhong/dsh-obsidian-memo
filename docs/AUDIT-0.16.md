# 0.16 发版前性能与结构稳定性排查

日期：2026-11-11。范围：0.16 系列开发期间的性能、结构与界面复核，包括设置与配置迁移功能；最终发布版本为 0.16.2。

## 结论

发现的主要问题是缓存失效范围过大、整库全文常驻、已有加载队列未被阅读组件复用，以及异步操作缺少设置会话边界。已完成针对性修复，未引入运行时依赖或构建工具。

现有卡片 memo、稳定回调、分批渲染、隐藏时暂停轮询、响应代次保护与扫描单飞值得保留。单文件 Client 约 6200 行，包含约 500 行样式、两套文案和组件；行数本身不能说明运行开销，但面板与设置的后续维护确实需要控制职责增长。

## 修复记录

| 问题及影响 | 修复 |
| --- | --- |
| 单文件 invalidate 同时清空 scanKey，下一轮误清整库缓存 | 仅删除该文件摘要及全文缓存，其他对象继续复用 |
| Scanner 常驻所有正文、blocks、评论，内存随整库正文增长 | 整库只保留摘要；全文按需读取，LRU 最多四篇 |
| Markdown 最终只返回 200 块，却先解析全部段落 | 展示块与标题齐全后跳过额外块解析；继续提取尾部评论，代码与引用示例不误识别；评论满额后也停止格式化 |
| 只按四舍五入的 mtime 与大小判断变化，可能漏掉原子替换 | 指纹加入完整 mtime/ctime、inode、birthtime；刷新时淘汰对应全文缓存 |
| 官方设置页复用便签墙轮询，扫描并传输整库便签 | 新增轻量 settings 读取，复用原轮询协调器和草稿组件 |
| state 整体进入配置串行队列，并发请求无法复用正在扫描的结果 | 仅配置刷新进入配置队列，扫描继续单飞；慢扫描不阻塞设置保存，目录切换使旧扫描重试 |
| AI、图片参数修改也清空扫描与图片路径缓存；unchanged 响应仍复制所有摘要 | 按字段失效，只在范围变化时清空；unchanged 跳过摘要装饰 |
| 阅读图片绕过卡片已有队列，打开多图笔记时同时请求全部本地图 | 提取 useNoteImage，卡片/阅读共用视口懒加载、三个并发与取消；阅读可复用卡片原图缓存 |
| 排序在每次比较时通过 localeCompare 重建带选项的比较器 | 复用一个 Intl.Collator，保持原排序规则 |
| 目录选择、新建、配置回调可能在关闭重开或切换仓库后修改新草稿 | 设置会话代次与仓库范围检查；系统选择返回真实 Promise，过期结果不进入新草稿 |
| 设置 JSON 与位置指针各自实现临时文件写入，失败可残留临时文件 | 共用 atomicWrite，保留私有配置权限并在失败时清理 |
| 普通 rename 在重名检查之后仍可能覆盖并发创建的目标 | 新建、改名、归档、归档撤回、删除恢复共用独占移动；不支持硬链接时独占复制，同文件大小写改名保留特例 |
| 合法正文经 JSON 转义后超过原 2 MiB 传输预算；上限与分发解析路径不一致 | 共用归一化 pathname；正文预算按最坏六倍转义推导，新建另加图片 base64 预算；文件与图片落盘限额保持不变 |
| 输入岛停用后附件 URL 未释放、归档撤回 token 长期积累、外部 JSON 数值隐式强制 | 补齐资源清理与过期回收，压缩参数只接受有限 number，界面显式转换输入 |
| 旧归档系统选择函数、initial/resolvedHint/onAddArchive、scanner.files 已无有效使用 | 删除死逻辑；文件移动与配置写入原语统一，减少重复实现 |

## 性能对照

同机 Node v22.22.3，同一个基准脚本：1000 篇便签，每篇约 72.27 KiB、2000 段；另测 5000 条打乱顺序的中文文件名。基线为本次排查前的 0.16 工作区快照。下表为单次对照，具体耗时会随 CPU、文件系统与缓存状态变化。

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 首次扫描 | 4205 ms | 938 ms |
| 无修改的缓存扫描 | 28 ms | 25 ms |
| 只改一篇后的扫描 | 4202 ms | 25 ms |
| 扫描后新增的保留 JS 堆 | 118 MiB | 2.19 MiB |
| 修改一篇后复用的摘要 | 0 / 999 | 999 / 999 |
| 5000 条文件名排序 | 258 ms | 9.72 ms |

内存数据是 GC 后进程 JS 堆的增量，不代表完整 DSH 进程、浏览器解码图片或页面 DOM 的总占用。基准不计测试数据生成时间。

运行 `pnpm bench` 可重现当前版本。脚本只使用自动清理的临时仓库，不访问用户配置或真实 Obsidian 仓库；可用 `node --expose-gc scripts/benchmark.mjs /path/to/checkout` 对照另一份源码。

## 结构判断与后续边界

Client 继续作为单文件浏览器 bundle 发布。已有数据、编辑、设置三个 hooks 的边界可以继续使用；本次让设置页与图片组件正确复用既有机制。后续若继续扩展设置，建议先拆开发源码中的样式/文案/设置视图，再生成同样的发布 bundle，并保留行为测试。仅拆文件不会消除扫描、传输或图片解码成本。

### 界面细节后的结构复核

本次未发现需要先重写架构才能继续新增功能的阻断点。Host 已把扫描、Markdown、设置、附件、回收站与系统打开器放在各自模块，Client 的读取、编辑、设置与图片加载也已有可复用边界。界面调整继续复用 copyNote、runDelete、撤回与原生配置加载链路，没有另建一套行为状态。右侧工具栏使用固定两行结构，同时移除已不再使用的窄面板阈值、分组布局与图标分支。

主要维护压力仍是 lib/client.js：目前约 6200 行，其中 StickyNotesPanel 约 1500 行，集中管理拖拽、整理、快捷键、弹窗与布局。继续增加较大功能时，优先按交互职责提取 hooks 或组件，并让数据、编辑、设置保留现有边界；样式和双语文案可随后拆为开发源文件，发布时仍生成单个 bundle。本轮没有为样式修改引入构建系统或状态库。

补充验证使用真实 Client 组件的本地浏览器预览：普通箭头光标、五种纸色标签与蒙层、深浅主题、四个操作的顺序及悬停提示、紫色 Obsidian 图文按钮独占第二行、320px 阅读面板、空正文提示、关于信息同排与窄设置页均通过，页面无脚本异常。此预览不等同于真实 DSH/Obsidian 的系统集成验收。中英文 README、指南、契约与本版变更记录已按最终界面同步，最终版本统一为 0.16.2。

仍保留以下边界：

1. 轮询仍遍历便签集合并 stat 文件；首次仍需读取正文。当前修复适合现有架构，超大库可再评估 Host 分页与真正虚拟列表。
2. 含图片删除仍要检查全库共享引用，这是保护其他笔记附件的必要校验。后续可考虑增量引用索引；本轮保留保守的删除规则。
3. 中途崩溃的孤儿附件尚无 journal；模板正文语义、自定义 Obsidian 配置目录、触摸交互等既有产品项仍见 [已知问题](KNOWN_ISSUES.md)。
4. 验证使用临时文件、Host RPC 集成测试与 Client hook/组件运行器；未连接真实 DSH/Obsidian 做界面验收。系统垃圾桶与网络盘/移动盘回退仍需要各目标环境实机验证。

本报告记录 0.16.2 发版前的可复现结果，不把代码与模拟测试通过等同于所有平台已经完成验收。
