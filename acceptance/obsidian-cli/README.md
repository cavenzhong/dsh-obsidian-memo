# Obsidian CLI 发布验收（macOS）

在可启动桌面应用的本机终端，从仓库根目录运行：

```sh
node acceptance/obsidian-cli/smoke.mjs
```

要求安装 `/Applications/Obsidian.app`（含 CLI）。脚本启动独立的 Obsidian 实例，使用临时 `HOME`、Electron 配置目录、CLI socket 和 mock keychain，不在个人库里创建文件。只有用两个库 ID 查到的真实路径都与临时库相符，才开始文件操作。脚本结束时关闭该实例，并打印临时测试目录供复核。

- 通过插件的 Host RPC 测试移动和撤销、归档和撤销、保存正文同时重命名、仅大小写改名。
- 读取 DSH 工作空间之外的 Markdown 文件，核查属性里的双链、标题链接及别名、块嵌入、普通 Markdown 链接；再查询 Obsidian 反链，确认目标 note 路径。
- 验证同名库之间互不影响、目标同名文件不被覆盖，关闭自动更新内部链接时拒绝改名且原正文不写入，「文件夹管理」不会更新双链。

`pnpm test` 不启动桌面应用；它不能替代此验收。

## 空文件夹设为库（桌面手动验收）

1. 新建一个不在现有 Obsidian 库内的临时空目录。在插件设置选「Obsidian CLI」，把临时目录填为仓库；确认显示「未设为 Obsidian 库」、「在 Obsidian 中设为库…」和开启「自动更新内部链接」的步骤。不要保存到日常使用的插件配置。
2. 点击「在 Obsidian 中设为库…」，确认打开 Obsidian 仓库管理器，而不是把目录直接改成库。在「打开本地仓库」选择**同一个临时目录**，确认 Obsidian 打开该库、目录下出现 `.obsidian`。
3. 回到插件点「重新检查」。设库按钮应消失；如果新库未开启「自动更新内部链接」，先确认插件显示对应警告，再按提示仅在测试库的「设置 → 文件与链接」开启该选项。CLI 已启用且可用时，重查应显示「CLI 可用」绿勾。
